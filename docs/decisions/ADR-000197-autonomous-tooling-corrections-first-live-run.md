# ADR-000197: Autonomous tooling corrections from the first live engine run

**Status:** ACCEPTED (human review 2026-09-24: the user asked for these changes in chat and chose each open option: named tickets first, then the inbox; recover and finish WORK-000316 first; fix the Qt 5 build trees in this request)
**Date:** 2026-09-24
**Work:** WORK-000319 (REQ-CHAT-20260924-013, process-change; also resolves REQ-AUTO-20260924-004)
**Requirements:** `development_operations.md` REQ-DEVOPS-016, REQ-DEVOPS-042 (amended); `autonomous_ticket_engine.md` TICKET-ENGINE-002, TICKET-ENGINE-006 (amended)
**Amends:** ADR-000090 (path ownership), ADR-000196 (external ticket engine)

## Context

RUN-20260924-113742 was the first live run of the external ticket engine
(VER-000317). It took one request end to end, but it and its end-of-run
review exposed several defects in the tooling around it:

1. **Directory registrations owned nothing.** `claim.py --own <request>
   --paths evidence/VER-000318` was accepted. Every ownership lookup
   (`own_paths`, `classify_worktree`, `commit_request`,
   `process_protection.protected_paths`) matches exact paths, so the eight
   evidence files the worker then wrote were "unowned". They would have been
   left out of the commit without an error. The worker had to
   `--adopt-existing-changes` its own files, which is the override that
   bypasses register-before-edit. A second live session had registered
   `evidence/VER-000319` the same way on the same day.
2. **git-sanity warned about pre-existing state.** Two files a human had
   staged before the attempt were still staged after it, as they should be.
   The check compared the index with nothing instead of with the attempt's
   baseline (`git_before`), and marked a clean attempt WARN.
3. **The stop reason misled.** A run started with one named ticket ended with
   "no eligible tickets left" while 21 requests sat in the inbox, because
   naming tickets restricted the run to them.
4. **Intake-timing phrases held tickets.** The engine withheld any request
   whose text said "do not perform (it) right now". The user stated that such
   a phrase only told the filing session to submit without starting: "Once
   the ticket is in the system, that message should be removed or ignored."
5. **Qt 5 build trees.** The shared debug build tree held 28 Makefiles
   generated by Qt 5 qmake. Its top-level Makefile had come from an IDE kit's
   Qt 5 qmake, and it regenerates subdirectory Makefiles with Qt 5. Plain
   `qmake` on that host was Qt 5 (qtchooser). The release tree held five,
   including a shipped vendored library. `scripts/run_tests.py` named only
   four of the Debug tree's and scanned one level deep. The user: "There should be no QT 5
   makefiles, everything should be QT 6."
6. **The control panel trapped the operator.** "View the queue" and "view the
   last audit" piped into `less`. Its only exit, `q`, was never shown.
   Enter, Esc and Space did nothing, and Ctrl+C killed the panel.

## Decision

1. **A registration owns exactly one file.** A path's baseline is its content
   (REQ-DEVOPS-042), and a directory has none. `claim.py --own` refuses an
   existing directory, the repository root and a path written as a directory
   (trailing `/`) before recording anything, so a call naming several paths
   registers none. Adoption (`--adopt-existing-changes`) stays per file and
   explicit. A path registered before it existed can still turn out to be a
   directory, and claims recorded earlier may hold directory entries. For
   those, `commit_request.py` refuses the commit and names every changed file
   under the entry that no request registered. It does not leave them out
   without a word. Files another request registered there stay that
   request's.

   *Rejected:* recursive directory ownership. Every file that appears under a
   registered directory would be committed as the request's, including files
   another session writes there without registering them. Today such files
   are "unowned" and never committed by anyone. That weakens the safeguard to
   make the workflow convenient. It would also need prefix-aware matching in
   every consumer (claims, conflicts, commits, worktree classification,
   process protection, test selection), and one missed consumer is a bypass.
2. **Selection: named tickets first, then the queue.** The operator's named
   tickets run first, in the operator's order, and bypass the type filters.
   Then come the tickets the engine started and has not finished, then the
   inbox in the project's order. The run ends at its ticket limit, not when
   the named tickets are done; `--max-tickets` equal to the number named
   gives a run of only those. The control panel's default maximum is the
   larger of the number named and 3. A run that stops names the bound it hit
   and the number of runnable tickets left. When it found nothing to start,
   it says why each remaining inbox request was not runnable (for example
   "1 type PROCESS-CHANGE excluded"). An empty inbox is reported as such.
3. **No intake-timing holds.** A "do not perform (it) right now / at this
   time" phrase is an instruction to the session that filed the request. The
   engine does not withhold a request for it (`selection.hold_patterns`
   retired, ignored if present), and the worker instructions say it no longer
   applies. `PROCESS-CHANGE` requests stay excluded unless named: process
   protection requires human review. That rule is not about intake timing.
4. **git-sanity measures against the attempt's baseline.** Snapshots record
   each staged path's index blob. The attempt record keeps a `git_delta`:
   - staged before and unchanged (pre-existing, noted);
   - staged before but staged again with other content, or no longer staged
     (WARN);
   - newly staged, as a new file or a change to a tracked file (WARN);
   - modified or untracked before (pre-existing, noted);
   - created or modified during the attempt without staging (noted: the
     checkout is shared).

   The engine never stages, unstages or reverts anything.
5. **Build trees are Qt 6 only, and the tooling says so accurately.**
   - `scripts/run_tests.py` lists every Qt 5-generated Makefile, three levels
     deep, with the count.
   - A new engine check (`build-tree`) snapshots Makefile generators before
     and after each attempt. A defect already present is reported as
     pre-existing and not counted against the attempt. One that appears, or
     a Qt 5 Makefile regenerated in the attempt's window, is WARN, worded as
     the window rather than the worker. The audit's Environment section
     carries the pre-existing defect.
   - The project's release build script refuses to build a release tree that
     holds a Qt 5 Makefile (project-specific).
   - The worker instructions say `qmake6`, never plain `qmake` or `make qmake`
     in a Qt 5 Makefile.

   The existing trees were fixed in this work (the user's choice):
   the debug (28), release (5) and sanitizer (4) trees were regenerated with
   `qmake6`, using each Makefile's recorded
   arguments. Their Qt 5-built objects were cleaned, and the Debug and
   Release trees were rebuilt.
6. **Panel views print in place.** A view returns to the menu on Enter. Ctrl+C
   never closes the panel, and end of input exits instead of redrawing
   forever.

## Consequences

* A worker registers each file before creating it, including every file in a
  new `evidence/VER-NNNNNN/` directory. An agent that registers a directory
  gets an immediate, explicit refusal that tells it what to do. An agent
  whose registered path became a directory gets a refused commit that names
  the files, instead of evidence silently missing from the commit.
* A live session holding a directory entry (for example `evidence/VER-000319`)
  can no longer commit while unregistered files sit under it. The refusal
  names the remedy.
* Named runs now continue into the inbox. An operator who wants only the
  named tickets sets `--max-tickets` to their number.
* git-sanity and build-tree results in earlier runs' records keep their V1
  meaning. Re-validating an old attempt compares its `git_before` with the
  checkout as it is then.
* A project library's `$$files()` shadow-build staleness (REQ-AUTO-20260924-005)
  is unchanged and remains a separate request.
