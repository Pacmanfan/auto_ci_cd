# Verification Strategy

**Build (canonical):** `docs/verification/tests.md` — use the current shadow-build commands and record actual counts in evidence; prose counts in historical reports are not current authority.

**Test Intents:** `docs/verification/test-intents/` — per REQ (e.g., TEST-DEVOPS-001; PROJECT-SPECIFIC domain intents follow the same shape)

**Evidence location:** `evidence/` for durable verification records; generated screenshots/traces may remain in ignored `tmp/diag/` and must be linked from the evidence record.

**Workflow:** Request → Requirement → Work → Test → Evidence → Documentation → Audit (per `docs/requirements/development_operations.md`).
